## 1. Data Model Overview

### LegalEntity vs LegalPerson - Key Distinction

| Model | Purpose | Fields |
|-------|---------|--------|
| **LegalPerson** | Organization-specific data | `legal_name`, `legal_form`, `legal_form_uri`, `registration_date`, `governing_law` |
| **NaturalPerson** | Individual person data | `given_name`, `family_name`, `date_of_birth`, `nationality` |
| **LegalEntity** | Wrapper/container for either + common fields | `entity_type`, `physical_address`, `email`, `phone`, `info_uri`, `identifiers` |

**Why this hierarchy?**
1. **Polymorphism**: LegalEntity can be EITHER a company OR a person
2. **Shared fields**: Address, email, identifiers are the same for both types
3. **Separation**: Organization-specific data (legal_form) vs person-specific data (date_of_birth) are kept separate
4. **Single reference point**: RegisteredEntity and TrustServiceProvider both link to LegalEntity (not directly to LegalPerson)

```
                    ┌─────────────────┐
                    │   LegalPerson   │  ← Organization-specific fields
                    │   (company)     │     (legal_name, legal_form)
                    └────────┬────────┘
                             │ OneToOne
                             ▼
┌─────────────────┐    ┌─────────────────┐
│  NaturalPerson  │───►│   LegalEntity   │  ← Common fields for BOTH
│   (individual)  │    │   (wrapper)     │     (address, email, phone, identifiers)
└─────────────────┘    └────────┬────────┘
      OneToOne                  │
                                │ OneToOne / ForeignKey
                    ┌───────────┴───────────┐
                    ▼                       ▼
            RegisteredEntity        TrustServiceProvider
```

### Single Source of Truth: `LegalEntity`

`LegalEntity` is the central model for organization data. Both `RegisteredEntity` (wallet registration) and `TrustServiceProvider` (TSL entry) link to it, eliminating data duplication.

## 2. Key Relationships

| From | To | Type | Reason |
|------|-----|------|--------|
| `LegalEntity` → `RegisteredEntity` | OneToOne | One organization = one wallet registration |
| `LegalEntity` → `TrustServiceProvider` | ForeignKey (1:N) | One org can be in multiple TSL schemes |
| `TrustServiceProvider` → `TrustService` | ForeignKey (1:N) | One TSP has multiple services |
| `LegalEntity` → `LegalPerson` | OneToOne | Organization details |
| `LegalEntity` → `NaturalPerson` | OneToOne | Individual person details |

## 3. Navigation Between Models

**RegisteredEntity ↔ TrustServiceProvider** are linked through `LegalEntity`:

```
                         LegalEntity
                              │
           ┌──────────────────┼──────────────────┐
           │                                     │
      OneToOne                              ForeignKey
           │                                     │
           ▼                                     ▼
   RegisteredEntity              TrustServiceProvider(s)
```

**Code examples:**

```python
# From RegisteredEntity to TSPs
registered_entity.legal_entity.trust_service_providers.all()

# From TSP to RegisteredEntity
trust_service_provider.legal_entity.registered_entity
```

## 5. PID Issuer vs QEAA Provider

| Aspect | PID Issuer | QEAA Provider |
|--------|-----------|---------------|
| **What they issue** | Person Identification Data (PID) | Qualified Electronic Attestation of Attributes |
| **Content** | Core identity: name, DOB, nationality | Attributes: diploma, license, insurance |
| **Who can be one** | **Member State designated only** | Any Qualified Trust Service Provider |
| **Mandatory?** | Yes - every wallet MUST have PID | No - user chooses |
| **Trust level** | Highest - government-backed | High - legally equivalent to paper |
| **Example issuers** | Skatteverket (SE), BundID (DE) | Banks, universities, insurance |

### What They Issue

**PID (from PID_Issuer):**
```
- family_name: "Svensson"
- given_name: "Anna"
- birth_date: "1985-03-15"
- nationality: "SE"
- personal_identifier: "SESE198503151234"
```

**QEAA (from QEAA_Provider):**

University Diploma:
- degree: "Master of Science"
