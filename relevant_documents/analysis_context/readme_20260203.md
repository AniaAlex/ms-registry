# EUDI Wallet Trust Infrastructure - Data Model Schema

**Date:** 2026-02-03

## Overview

This schema implements the EUDI Wallet trust infrastructure based on:
- eIDAS 2.0 (Regulation 2024/1183)
- Trust Infrastructure Schema (WEBUILD WP4)
- ARF Topic 27 - Registration of PID Providers, Attestation Providers, and Relying Parties
- ETSI TS 119 612 - Trusted Lists

## Core Principle: Single Source of Truth

**`LegalEntity`** is the single source of organization data. Both `RegisteredEntity` (wallet registration) and `TrustServiceProvider` (TSL entry) link to it, eliminating data duplication.

## Key Relationships

| From | To | Type | Reason |
|------|-----|------|--------|
| `LegalEntity` → `RegisteredEntity` | OneToOne | One organization = one wallet registration |
| `LegalEntity` → `TrustServiceProvider` | ForeignKey (1:N) | One org can be in multiple TSL schemes |
| `TrustServiceProvider` → `TrustService` | ForeignKey (1:N) | One TSP has multiple services |
| `LegalEntity` → `LegalPerson` | OneToOne | Organization details |
| `LegalEntity` → `NaturalPerson` | OneToOne | Individual person details |

## Navigation Between RegisteredEntity and TrustServiceProvider

**Date:** 2026-02-03

`RegisteredEntity` and `TrustServiceProvider` are linked **through `LegalEntity`**:

```
                         LegalEntity
                              │
           ┌──────────────────┼──────────────────┐
           │                                     │
      OneToOne                              ForeignKey
           │                                     │
           ▼                                     ▼
   RegisteredEntity              TrustServiceProvider(s)
```

**To get TSPs from a RegisteredEntity:**
```python
registered_entity.legal_entity.trust_service_providers.all()
```

**To get RegisteredEntity from a TSP:**
```python
trust_service_provider.legal_entity.registered_entity
```

Both models share the same organization data (name, address, contact) through `LegalEntity` - no duplication.
